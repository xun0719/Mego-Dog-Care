# 就醫紀錄模組

- `medicalVisitContent.ts`：用藥預設值與日期格式轉換。
- `medicalVisitDetailContent.ts`：詳情列與日期格式轉換。
- `components/MedicalVisitTextField.tsx`：共用文字欄位外觀。
- `components/MedicalVisitMedicationEditor.tsx`：單筆用藥編輯區。
- 當次開藥表單先顯示藥袋名稱及使用說明，日期、頻次、飯前／飯後與備註放在可展開的「補充服用資訊」；有錯誤時自動展開。每日次數原有預設與 1～10 次限制不變，標籤改為「新增藥物時必填」，不再誤標選填。
- 每日次數與新增用藥共用 `../medications/components/MedicationFrequencyField.tsx`，以置中的單一欄位開啟選單，不再要求輸入數字；就醫仍可選到 10 次。取消不改值，選擇頻次不建立提醒。飯前／飯後／不限為三個等寬、文字置中的單選按鈕；藥袋名稱與使用說明維持靠左。
- 藥袋說明欄與「補充／收合服用資訊」之間留 16，多筆藥物卡片及「新增一筆用藥」入口也保留 16。詳情中建立／查看用藥療程按鈕與開藥文字分開，藥物卡片之間留 16；展開、收合及有錯誤自動展開時使用相同間距。
- 當次開藥的說明文字使用完整可用欄寬與 20 行距，不再固定限制寬度 280。最終儲存與其他照護表單共用 `FORM_ACTION_GAP`（24）。
- 此區只保存當次看診開藥內容，不會自動建立服藥提醒。儲存後在詳情可「建立用藥療程」，帶入資料並由使用者確認；建立後改為「查看用藥療程」。來源內容與後續療程不互相覆寫，刪除就醫紀錄也不刪除已建立的療程。
- 就醫詳情的 GET 會一次查詢此就醫的關聯療程，再為開藥卡加入唯讀 `sourceMedicationKey`／`linkedMedicationId`。編輯及複製就醫時只送正式用藥欄位，不將唯讀關聯資訊送回驗證模型。詳細來源規則見 `../medications/README.md`。
- `components/MedicalVisitDetailSections.tsx`：詳情狀態、資料列、藥物卡。
- `screens/MedicalVisitFormScreen.tsx`：表單狀態、驗證、儲存 API、回診提醒同步。
- `screens/MedicalVisitDetailScreen.tsx`：讀取、編輯、刪除、分享與附件操作。

詳情頁將編輯與分享摘要列為主要操作，刪除獨立放在其後作次要操作；分享及附件流程保留。刪除確認補充「已建立療程會保留」，詳情 API 另附唯讀療程關聯資訊。

表單驗證、就醫 API、附件上傳與導航仍保留在畫面層；UI 子元件不發送請求。

表單的就醫地圖入口帶入 `selectForVisit`，選院後以 `popTo` 合併醫院名稱到既有表單，不重建空白表單。從首頁急診地圖、AI 照護工具或就醫列表進入時只瀏覽；已儲存的就醫照片可從紀錄頁右上角的「照護相簿」查看，仍回到原始就醫紀錄編輯或刪除，不複製資料。

「從地圖選擇動物醫院」是與名稱欄位間隔 12 的等寬淡綠描邊按鈕，有地圖圖示、箭頭及按壓回饋。回診日期使用共用日期欄位的置中呈現與清除按鈕，清除後一併取消回診提醒；仍保留原本的日期時間模式與範圍驗證。

「是否建立回診提醒？」與疫苗／驅蟲共用 `components/ReminderToggleField.tsx`。文字區彈性換行，Switch 固定在外框右側並垂直置中，開啟時淡綠底；沒有下次回診日期時保留停用說明，不再整區隱藏。儲存時停用開關。日期清除按鈕位於標題右側，避免日期框下方多一個短按鈕。

日期顯示與表單的用藥日期共用 `utils/taipeiDate.ts`，以台灣時區解析和輸出，不再使用沒有時區的日期字串或重複的本機日期轉換函式。

表單錯誤顯示在欄位下方並自動捲到第一個出錯的欄位，狀態由共用的 `hooks/useFormFieldErrors.ts` 管理——此做法原本只在這個模組，已抽出供其他表單使用。儲存成功直接返回，不另外提示；只有建立了回診提醒而手機通知未排定時才顯示，並附「前往設定」。
