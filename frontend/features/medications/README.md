# 用藥管理模組

## 入口

- 列表：`screens/MedicationListScreen.tsx`
- 新增／編輯：`screens/MedicationFormScreen.tsx`
- 詳細資料：`screens/MedicationDetailScreen.tsx`

## 資料流

`Screen → services/medicationService.ts → /api/medications → backend service → MongoDB`

## 對應職責

- `types.ts`：表單型別、預設值與顯示文字。
- `medicationStyles.ts`：三個畫面共用樣式。
- `components/MedicationFrequencyField.tsx`：置中的單一欄位，例如「每天 2 次 ˅」，點擊後開啟可捲動的次數選單；用藥療程提供 1～6 次，就醫開藥提供 1～10 次。左右圖示槽同寬，箭頭及勾選不會擠偏文字；選取後立即回填，取消、點擊外側或系統返回不改值。次數僅記錄醫囑，不決定或推薦頻次。
- `components/MedicationDetailRow.tsx`：詳細資料列。
- `screens/`：只負責畫面組裝、導航與使用者操作。

詳細頁的編輯／複製按鈕使用一致尺寸；選填補充備註未填時不顯示。完成、停止、刪除療程與提醒的既有確認和資料流程不變。

## 選擇樣式與就醫銜接

- 每日次數使用獨立選單，不再將六個選項全部攤開。飯前／飯後／不限採三個等寬的 `components/SelectionChip.tsx`，單選文字直接置中，以淡底、邊框及字重區分，不預留單邊圖示；多選保留勾選，左右同寬留位。藥品名稱及使用說明維持靠左。每日次數不會自動產生提醒時間；使用者需另外設定。
- 相鄰控制項以 `FormTokens.FORM_FIELD_GAP`（16）分開；最終儲存按鈕使用 `FORM_ACTION_GAP`（24）。提醒清單只在有時間時加入外部留白，列與列間距 12，不會把同一欄的編輯／刪除按鈕拆開。詳細頁完成／停止療程與刪除操作也保留獨立間距；不在共用 `AppButton` 上一律加外距。
- 已儲存就醫紀錄的當次開藥項目可選「建立用藥療程」，帶入藥袋名稱、說明、頻次、日期、飯前／飯後與備註；仍需在療程表單確認後儲存，提醒預設關閉。
- 沒有藥物開始日期時使用該次就醫的台灣日期；不把舊就醫的療程誤設成今天開始。就醫紀錄允許每日 1～10 次，療程目前僅支援 1～6 次，超出時保留原值並停用匯入，不自動減少次數。
- `medicalVisitId` 與 `medicalVisitMedicationKey` 對應該次就醫及開藥內容快照；來源鍵由後端依正式欄位產生，忽略顯示用欄位與字串前後空白。同一份內容的重送與並發建立以唯一索引／原子 upsert 取得同一份療程，不覆寫既有內容或重建提醒。
- 已建立的開藥項目改顯示「查看用藥療程」。就醫快照與療程彼此獨立，不互相覆寫；更正／刪除當次內容不會自動更改／刪除療程。開藥內容修改後來源快照不同，若只是更正既有療程，請直接編輯該療程，不需再建立。
- 編輯療程不可換綁來源；複製新增會清除來源關聯、日期與提醒，作為新的療程。刪除療程後，原開藥紀錄仍保留，可以再建立。
- 後端 `app/services/medication_source.py` 維護來源鍵及詳情關聯；不需刪除／遷移既有資料，也不新增舊資料判斷分支。
- `__tests__/medicationFlow.test.tsx` 涵蓋次數選單、取消不改值、就醫高頻次保留、等寬服用方式、帶入後確認、提醒預設關閉、複製清除來源、已建立入口切換、超出頻次與就醫服用資訊收合。後端 `tests/test_medication_source.py` 檢查來源變更、權限、重送及並發情境，使用隔離替身，不操作實際飼主資料。小螢幕及放大字體的實際視覺仍需手機驗收。

## 保留行為

新增、編輯、複製新增、完成療程、停止療程、刪除及提醒時間操作保留。既有 API 欄位保留，另新增選填的 `medicalVisitMedicationKey` 用於就醫來源辨識；一般新增療程不需要提供。

## 錯誤與儲存回饋

清單支援下拉更新。表單的檢查不使用對話框：藥品名稱、結束日期順序、每日次數與提醒時間上限的錯誤顯示在各自欄位下方（`components/FieldError.tsx`），送出時自動捲到第一個出錯的欄位並震動一次，開始修改該欄即清除訊息，狀態由 `hooks/useFormFieldErrors.ts` 管理。儲存成功直接換到詳細頁，不另外提示；只有手機通知沒排成功時才顯示提醒。
